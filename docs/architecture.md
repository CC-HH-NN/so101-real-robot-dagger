# 系统结构与闭环边界

这个项目把抓放任务当作真机闭环的验证载体。公开代码只展示几个关键边界，完整硬件驱动和内部部署服务不放入公开副本。

```text
双摄 RGB + 关节反馈
          ↓
观测时间对齐、数据记录与模型输入
          ↓
ACT / 远程 Diffusion Policy / π0 / π0.5 RTC
          ↓
推理服务、动作块接续、相机时效和延迟记录
          ↓
串口执行、关节反馈、硬件状态与人工评分
          ↓
结果归因：模型 / 数据 / 延迟 / 通信 / 硬件

DAgger 分支：模型自主执行 → 人工接管 → 完成剩余任务
          ↓
完整轨迹归档 + intervention 标记 → 连续纠正窗口 → 再训练 → 泛化复测
```

## 模块职责

| 模块 | 作用 |
| --- | --- |
| 观测与记录 | 保存双摄、关节状态、时间戳、模型目标、实发命令和实测反馈。 |
| 策略适配 | 让 ACT、Diffusion Policy、π0、π0.5 和 RTC 使用统一的输入输出与评分边界。 |
| 执行与诊断 | 处理动作块接续、相机时效、网络往返、串口反馈和硬件状态。 |
| DAgger 会话 | 在失败后切换人工接管，保存完整轨迹并标记自主/人工阶段。 |
| 训练准备 | 从连续有效的人工纠正窗口生成监督数据，保留来源和时间轴信息。 |
| 评测与展示 | 用固定点位和两种位置变化复测，并提供结果表和精选视频。 |
| RTC 日志分析 | 从逐事件真机日志提取延迟、接续、队列和动作连续性指标，生成公开汇总表。 |

公开的 `src/` 目录只保留与这些边界直接相关的实现：DAgger 会话控制、纠正数据时间轴处理、训练窗口采样以及 RTC 动作接续。完整硬件驱动、部署服务和内部路径不放入公开副本。
