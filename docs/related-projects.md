# 公开 SO-101 项目调研

调研日期：2026-11-13。选取的项目覆盖真机模仿学习、全栈 SO-101 工具链和 NVIDIA 的 sim-to-real 教程，用来比较公开仓库如何安排信息、结果和视频入口。

| 项目 | README 的组织方式 | 可借鉴的写法 |
| --- | --- | --- |
| [JereoZero/so101-real](https://github.com/JereoZero/so101-real) | 开头交代任务、硬件、算法和数据规模，随后记录 LeRobot 版本差异、视频解码后端、数据合并、训练、推理和真机结果。 | 先交代任务和证据，再展开版本差异与排错；把成功率和运行条件放在同一处。 |
| [EmbodiedFX/LeRobot-SO101](https://github.com/EmbodiedFX/LeRobot-SO101) | 以“数据采集 → 模型微调 → 真机推理”组织全文，补充 Mac 环境、装配、相机和串口准备。 | 让读者先理解闭环，再进入硬件细节；操作顺序与实验顺序一致。 |

| [phospho/phosphobot](https://github.com/phospho-app/phosphobot) | 先用一句话说明支持的机器人和能力，再以快速开始串起连接、采集、训练和控制。 | 保持首页入口简洁，把采集、训练和部署作为一条可读流程。 |

## 形成的公开副本结构

综合这些项目的共同模式，本仓库采用以下顺序：

1. 先给固定点位结果、位置泛化、训练曲线和可直接查看的 Demo；
2. 再说明观测、数据、训练、推理、执行和失败归因如何连接；
3. 将固定点位、位置泛化、DAgger 和技术故障分开统计；
4. 用项目历程、系统架构、故障复盘和结果溯源文件承载细节；
5. 通过 `results/`、`docs/` 和 `assets/` 建立结果、说明与视觉证据之间的对应关系。

本项目借鉴这些仓库的信息结构与证据组织方式，结果、代码和视频仍来自本项目自己的 SO-101 真机流程。
